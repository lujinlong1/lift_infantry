# 前轴伸出接触找零（2026-10-13，替代之前的缩回找零操作）

用户确认：ch0/ch1 为前辅助轮，ch2/ch3 为后麦轮。后轴落地启动时已处于机械最低点。前轴的零点是伸出后接触底盘的承重点，继续伸出仍可以抬升车身，并不是不能继续运动的机械硬挡块。

## 当前实现

- 前轴只向逻辑正方向伸出，不执行缩回、前置反向运动或 BACKOFF。使用独立参数 `g_lift_control_debug.homing_contact_current`，默认 +1500，沿用上一版寻零电流的大小，未扩大电流上限；该值尚未在接触找零工况下实测整定。
- 若修改接触寻零电流，需完整 `apply=1` 重建找零参数，再重新确认后轴最低点并启动；`apply_gains` 只重载正常控制和保护参数，不重载找零参数。
- 接触传感器尚未接入。电机连续低速/停转 300 ms 只让该轴停止电流并进入待确认状态，不自动认定为接触；这样初始已接触和摩擦卡滞都不会被错误自动置零。
- 操作手看到实际接触后，通过 Watch 的逐轴确认输入记录该轴当时的编码器位置为接触零点，并立即停止该轴寻零电流。转速在原阈值内稳定 300 ms 后，该轴变为 DONE。不执行反向退出，记录的是确认当时的接触位置，不是停稳后重新覆盖的位置。
- 后轴保持上一版的当次最低点确认逻辑，找零期间运动电流为 0；反馈掉线仍让整组故障。
- 四轴全部 DONE 才进入 READY。尚未发过有效且使能的运动命令时，READY 空闲期间输出 0，不启动“命令过期”缓降；正常升降第一次使能后，原来的超时缓降、堵转及掉线保护继续有效。清零点或重新建立零点会重置这个首次使能状态。
- 前轴的可用抬升行程须以新的接触零点复核，先完成小行程测试再扩大；原有软限位没有扩大。

## Watch 操作

1. 退出旧调试会话，下载最新 HEX/AXF，重新进入调试并运行。确认四轴在线、output_gate=0、旧台架/CAN 点动未占用。
2. 如果保留旧故障，先写 `g_lift_task_command.reset_request=1`。如果已有旧零点，另写 `g_lift_task_command.clear_homing_request=1`，等待 homed=0。
3. 在车身有机械支撑、后轴确实在最低点时，依次写：

   ```c
   g_lift_task_command.rear_at_minimum_confirmed = 1
   g_lift_task_command.homing_request = 1
   ```

4. 前轴伸出。当某根实际接触底盘承重点时，写 `g_lift_task_command.front_contact_confirmed_mask`：

   | 值 | 确认的轴 |
   |---:|---|
   | 1 | 仅 ch0 |
   | 2 | 仅 ch1 |
   | 3 | ch0、ch1 均已实际接触 |

   该字段每次消费后清为 0。不要求两根同时接触；可先写 1，等另一根接触再写 2。不要在尚未接触时预先写入，不要把静摩擦造成的停转确认成接触。

5. 预期 homed=1、state=2、fault=0，homing_state[0..3]=4，homing_fault[0..3]=0。没有运动命令时，command_fresh=0 可以保持，但不会因此开始缓降。

## 状态与故障

- homing_state=2：正在寻接触，前轴电流逻辑为正；ch0 原始电流为负，ch1 原始电流为正。
- homing_state=6：低速/停转候选，已停止出力，等待操作手核实实际接触。
- homing_state=7：接触位置已记录，停止出力等待转速稳定。
- homing_state=4：该轴零点建立完成。
- 寻接触仍保留原 8 秒运动超时；进入待确认/待停稳后最多等 60 秒，超时 homing_fault=6。等待确认不继续给寻零电流。
- 若前轴 state=6 但实际没接触，应检查它的静摩擦、接线、方向和当前出力，不能确认零点。

用户上一张截图中 homed=1、四轴 homing_state=4 / homing_fault=0，表示找零确实成功；state=3、fault=2、guard_state=4、guard_fault=2 表示之后在没有新鲜命令时自动缓降，并遇到缓降堵转。上述首次使能处理修复的是这一运行路径，不取消已经开始升降后的命令超时保护。
