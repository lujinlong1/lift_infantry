- `L0`：编译和静态检查。
- `L1`：纯软件/协议测试，包含坏帧、超时和边界值。

## TEST-20260929-002：抬升四个控制模块的 L1 主机验证

- 关联议题：LIFT-005、LIFT-006、LIFT-008、LIFT-009、LIFT-013
- 固件来源：**无**。模块尚未进入本工程，暂存在学习仓库
  `plans\_lift_prep\`（`lift_homing` / `lift_sync` / `lift_guard` / `lift_control` /
  `lift_top` / `lift_seq` / `lift_geometry` / `lift_telemetry`）。
  其中 `lift_control` 链接的是本工程真实的 `Algorithms/Pid/Src/pid.c`。
- 硬件版本与接线：无（纯主机仿真，不涉及实物）
- 参数集版本：仿真参数，**全部为占位值，未标定**
- 验证等级：**L1**
- 环境与前置条件：
  - Windows + MSYS2 UCRT64 `gcc`（x86_64-w64-mingw32 16.2.0）
  - 严格标志：`-std=c11 -Wall -Wextra -Wpedantic -Werror`
  - 驱动脚本：`plans\_lift_prep\run_tests.ps1`（ASCII-only，避免 PS 5.1 按 ANSI 解析）
  - 注意：MinGW 的 `ld` 无法处理含中文的输出路径，故可执行文件输出到纯 ASCII 临时目录
- 操作步骤：`powershell -ExecutionPolicy Bypass -File run_tests.ps1`
- 预期结果（量化）：五个套件全部编译零警告，断言失败数为 0
- 实际结果：

  | 套件 | 断言 | 结果 |
  |---|---:|---|
  | `lift_homing` | 54 | 通过 |
  | `lift_guard` | 63 | 通过 |
  | `lift_sync` | 205 | 通过 |
  | `lift_control` | 21 | 通过 |
  | `lift_system`（整链集成） | 201 | 通过 |
  | `lift_top`（编排层集成） | 40 | 通过 |
  | `lift_seq`（时序执行器） | 48 | 通过 |
  | `lift_geometry`（换算） | 144 | 通过 |
  | `lift_telemetry`（遥测） | 78 | 通过 |
  | **合计** | **854** | **全部通过** |

  整链集成仿真覆盖四个阶段：
  - P0 找零之前，上层即使硬给 3000 电流也必须被门禁拦为 0
  - P1 四轴同时堵转找零，零点落在机械死点上，且过程中不得报故障
  - P2 使能抬升后高度收敛，全链下发电流的翘曲分量严格为 0
  - P3 上层命令超时后受控缓降到底并进入 `PARKED`，不得掉下来、不得放行大请求

  编排层（`lift_top`）另外覆盖：未找零门禁、四轴找零编排、找零失败整组锁存、
  复位后重新找零、以及"已找零时不得直接重新找零（必须两步）"这条约定。

  时序执行器（`lift_seq`）另外覆盖：MOVE 到位后稳定计时、WAIT 进入时锁定当前姿态、
  只认确认沿推进、超时、中止、`require_confirm` 的两段式、STOP 收尾、
  以及故障锁存与复位。**注意：被验证的是执行器，不是台阶动作表**——
  动作表尚未填写，见 `抬升模块架构.md` 第 4 节。

  换算模块（`lift_geometry`）另外覆盖：整圈精确往返、传动比、非法配置拒绝、
  溢出饱和，以及**同一个 `speed_rpm` 在"转子侧/输出侧"两种解释下相差约 19 倍**
  这一条断言——它把"转速语义未确认"这件事从注释变成了可执行的证据。
  **注意：导程、传动比、转速语义全是占位值，标定前任何毫米数值都只是估算。**

  遥测模块（`lift_telemetry`）另外覆盖：原始反馈原样复制、模态由已找零位置正变换、
  模块未接入时字段归零不残留、**故障计数只在跃迁进故障时 +1**（持续故障不重复计数）、
  JustFloat 帧尾与 16 通道布局、以及缓冲区不足时拒绝且不写入。

- 结论：**通过（L1）**
- 异常和后续动作：
  1. 集成测试首次运行报 7 项失败，**全部不是代码 bug，而是断言/理解写错**：
     - 5 项：断言"找零后停在机械死点"。实际上 `lift_homing` 找到死点后**会回退
       `backoff_ecd` 离开死点**（ADR-007 的本意）。断言已改为"已离开死点且未冲过头"。
     - 2 项：断言"单角偏差只进入翘曲模态"。**错的**——按权重表，右后角抬高 400
       会同时进入四个模态（height +400 / roll −400 / pitch −400 / warp −400）。
       只有 `[+1,−1,+1,−1]` 这个特定组合才是纯翘曲。该反面教材已保留为断言。
  2. 顺带暴露一个**真实调参陷阱**：仿真中 `backoff_ecd = 500`（计数），
     但一个控制周期的位移达 1600 计数，实际回退冲过 3 倍。
     实机上同理，`backoff_ecd` 必须 ≥ `backoff_current × 机械增益 × 周期`，
     否则需在接近目标时降低回退电流。**已加入 LIFT-007 标定清单。**
  3. **本次验证不能替代任何实机验证**：未跑 Keil、未进固件工程、无实物数据；
     控制周期、任务优先级、栈用量、CPU 占用全部未测。
     详见 `抬升模块架构.md` 第 4 节。
