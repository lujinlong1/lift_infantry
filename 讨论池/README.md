# 抬升步兵讨论池

这里是四丝杆抬升步兵后续开发的唯一讨论入口，用来把“想法、证据、决定、实现、实车结果”串起来。

本工程从英雄工程 `D:\rm\hero_refactor\hero_firmware` 迁移而来；
议题用 `LIFT-` 编号，电机编号见 `电机映射表.md`。

## 使用顺序

1. 新想法先写入 `议题池.md`，分配编号和优先级。
2. 涉及赛事约束时，先在 `资料索引.md` 找官方依据。
3. 需要统一口径的数据写入 `规则与数据字典.md`，禁止只留在聊天里。
4. 方案被确认后写入 `决策记录.md`，同时记录被否决方案和原因。
5. 烧录、台架、实车结果写入 `验证记录.md`，用数据决定议题是否关闭。

## 状态

`待澄清` -> `待方案` -> `待决定` -> `待实现` -> `待验证` -> `已完成`

遇到阻塞使用 `阻塞`，并写清解除条件。不能用“代码写完”代替“已完成”；控制功能必须经过对应级别的验证。

## 优先级

- `P0`：可能失控、损坏硬件、违反规则，或阻塞所有后续工作。
- `P1`：比赛核心能力或可靠性问题。
- `P2`：性能、可维护性和调试效率。
- `P3`：体验与长期改进。

## 议题最小信息

每条议题至少包含：问题、现象/证据、目标、约束、候选方案、验收标准、状态。参数调整必须同时记录固件版本、硬件配置和测试条件。
